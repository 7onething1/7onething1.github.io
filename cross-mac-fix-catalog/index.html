The one that mattered most

skill-sync-2026-08-12-session-audit-meter-fix. Its own first line says the other Mac's copy of analyze.py inflates every token figure and reports a batching rate that cannot ever be non-zero. The cause: Claude Code writes one JSONL record per content block, so a message carrying three parallel calls becomes three records of one call each, and a per-record test never sees a batched turn. This Mac's analyze.py does carry the fix, dated 2026-08-12, so its 6% reading is sound. My own hand-rolled parser did not, which is how I came to publish a 0.0% rate for this session and build a hook on it. Re-measured keyed on message.id: record-split ratio 2.41, 128 tool turns, 42 batched, 32.8%. The hook carried the same defect and would have fired forever on a well-batched session; it is fixed and re-proved on 8 of 8 controls. One file from that bundle, remeasure.py, is still missing here.

How install status was judged

A payload file counts as INSTALLED only when a file of the same basename exists
under one of these roots AND its sha256 matches the copy in the bundle:

  ~/.claude/hooks        ~/.claude/skills        ~/.claude/skills_disabled
  ~/.claude/projects/-Users-drwu/memory          ~/Projects        ~/scripts

A same-named file whose digest differs is reported as DRIFTED rather than as
installed, so a stale local copy cannot pass as applied. Punctuation in the extracted descriptions is normalised to commas, since the
house voice ruleset bans the em-dash and these are truncated summaries rather
than attributed quotations. Request bundles this
Mac SENT are included for completeness; their "missing" files are usually
outputs that only ever existed on the other machine, which is why the per-row
detail matters more than the total.
