Why one pass and not fifty hooks. Thirteen Stop hooks already produced 82 blocks in three days, each costing a full turn, and one of them (ask_drift_gate) caused 30 of those by reading a peer session's message as the user. Fifty separate processes would multiply that cost. These 50 run as 50 checks inside a single hook.

Prior art was checked first. session-fraud-check already carries 54 regex-over-file patterns and is wired. It cannot express session shape, which is what nearly every failure here actually was: turn counts, session age, idle minutes, unreturned tool calls, peer-sender counts, ask overlap. These 50 cover only that gap.
