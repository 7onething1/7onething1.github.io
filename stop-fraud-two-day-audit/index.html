The 599 toms, in full

One incident produced three of the eleven gates, so it is worth reading whole.

On 2026-09-07 at 23:02, a session wrote 599 tom notes into a Zappa ballad whose author had written 6, and shipped it. Twenty minutes later Brandon answered: “Over did it those toms are fraud.”

Every statistic in that turn was true.

attribution vs the isolated kick stem     0.27x of chance    true
attribution vs the isolated snare stem    0.52x of chance    true
median decay                              348 ms             true
two fundamental modes, clean split                           true

Not one of them asked how many toms a drummer plays in a slow ballad. Six per bar is refuted before any statistic runs.

The mechanism had a name. The tom lane held only 6 written events, too few to calibrate against, so intensity was scored against the candidate population's own median. A yardstick cut from the population cannot reject that population. Whatever the junk level is becomes the standard, and 650 of 662 candidates passed.

The proof block that shipped it was seven rows of self-agreement:

high tom          415 of 415  OK
low tom           184 of 184  OK
kick              398 of 398  OK
pedal hi-hat      286 of 286  OK
snare ghosts      147 of 147  OK
ride accents      409 of 409  OK

Each row confirmed the upload arrived. Not one could have failed. And the size of the change was disclosed, at the very bottom, as a dial to adjust later: “the toms are the biggest single change yet, 599 against the author's 6.”

Two more, found by a second session

While this page was being built, another session working on the chat babysitter reported two detector defects. Both were verified here against the code before anything was encoded. A peer report needs its own verification before it counts as a measurement.

An alarm narrower than its own detector. The alert path filtered on 7 rule names. The sweep emits 14 distinct rule types across the 137 alert rows on disk. The daemon’s own comment records the cost: “39 of 57 live findings could never alert and the log read new_alerts=0 for hours while CEILING_BREACH, SCOPE_DRIFT and DONE_NO_PROOF piled up unseen.” That is G62.

A change key that freezes on silence. The dedup key was uuid:rules:floor(turns/500). A chat that goes quiet stops accruing turns, so its key can never change, and silence is the exact condition worth re-alerting on. One chat alerted once at 8.9 days idle and never again. That is G63.

Both generalise past the babysitter. Any checker paired with a reporter can have the first defect, and any change-detection key built only from counters can have the second.

Three new skills

/fraud-firewall, one command and one verdict

python3 ~/.claude/skills/fraud-firewall/firewall.py --draft closing_block.md

Answers “what skill we can build to elminate all fraud” from 09-07 19:37. It composes the five checkers that existed before it and were being run by raw path, one at a time, or not at all: 63 gates, 54 fraud patterns, completion-control, say-it-plain and reference-class. A component that fails to execute is reported as ERROR and blocks the verdict, because a checker that did not run is not a checker that passed. That rule caught its own first bug: run_gates.py reads stdin as a Stop hook and hung for 120 seconds until the firewall closed stdin.

/reference-class, did this number earn the right to ship

python3 ~/.claude/skills/reference-class/refclass.py --wrote 599 --source 6 --unit toms --span-bars 103 --threshold-from candidates --pass-rate 650/662

Six checks: a threshold cut from the population it filters, a magnitude of ten times or more, a per-bar density no player would play, a filter that passes almost every candidate, a missing chance baseline, and a number no saved script can regenerate. Run against the 599-tom ship it returns 6 of 6 STOP. Run against the snare pass from the same session that Brandon accepted, it returns PASS.

/say-it-plain, measure the reply before sending it

python3 ~/.claude/skills/say-it-plain/sayplain.py draft.md

Brandon asked for this four times in 32 hours, in four different chats. Five limits: fourteen lines, one question, two sentences over 25 words, six raw identifiers, four jargon words. Fenced code is exempt, so a proof block of paths and http codes never counts against the prose. The reply that shipped 599 toms scores 51 lines against a limit of 14.
