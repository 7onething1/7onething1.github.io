What this is, and what it is not

Five sessions were running on this song at once. The chat titled Final watermelon was three minutes ahead on the file build, so this session did not build a competing .gp and did not write to s6857183. This page is the measurement, so the decision can be made by ear the way index 24 was.

Every number is read from the live drums payload of r8968524, or from the skill's own gates run on candidate v11. Nothing here is an edit.

A reader bug in the skill, found and fixed

tr_ledger.py resolved percussion only through Property name="Element". GP7 and GP8 carry the kit index in <InstrumentArticulation> instead, so every drum note read as midi -1 and tr_gate.py track called this a 100 percent off-GM-map, not a drum staff. A second fault sat behind it: these notes also carry Property name="Midi" holding the pitched value, which shadowed the articulation even once the index was found.

Both are patched. The gate now reads drum staff with lanes 36, 40, 41, 44, 45, 46, 47, 48, 49, 51, 57, and the census returns ride 1525, kick 505, snare 340, pedal hi-hat 245, which matches the live tab. All skill self-tests still exit 0. Backup at tr_ledger.py.bak-pre-instrumentarticulation-2026-09-08.

One cosmetic issue left alone: tr_score.py line 546 truncates its JSON dump at 8000 characters, so the CLI emits unparseable JSON on a long result. Call hands_gate() directly instead.

Red zone, corrected

An earlier note from this session claimed 20 of these measures were red zone because they are 5/4. The skill's own redzone disagrees: it returns red_zone_bars [54], tuplets only, with no odd-meter or meter-change bars. So 19 of the 20 are repairable and index 54 is the one that needs its rational positions from a written source.

The file's own subdivision vocabulary is 1, 2, 4, 8, 16, 32, 64, finest 64, with 32nds appearing 90 times and 64ths 40. A 32nd is therefore legal here, and the 41 sub-16th tom beats below still need affirmative evidence rather than a leftover from an unsnapped onset.
