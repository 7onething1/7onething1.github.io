1. The short answer

The MacBook did not find a faster setting. It wrote its wasted time down as ten named mistakes, each with an executable fix. Its own first finding was that switching off 52 unused skills buys nothing: they load as bare names, roughly 1,300 characters of an 88,000-token start. The waiting is the model thinking. So the gain came from the list of mistakes, not from configuration, and the same method applied here turns up one failure far larger than anything on the MacBook's list.

Ten mistakes, each paired with a fix. Six are about picking the wrong route and paying for it in round trips.

4. Where this Mac's written gate failed

Batching has been a hard gate in CLAUDE.md since the 2026-07-19 session audit, and it has a memory file of its own. Both are prose. Here is what prose produced:

CLAUDE.md, since 2026-07-19 : "independent tool calls go out in ONE block, target above 40%"
measured 2026-10-19         : 540 of 9,009 turns batched = 6%
one session the same day    : 64 tool turns, 0 batched = 0.0%
The lesson generalizes past batching. Of the 52 hooks on this Mac, none measured tool-call shape. Every other hard gate that holds here holds because something runs and refuses: the deploy gate, the delete block, the voice gate, the stop gate. The rules that live only in a document are the ones that drift, and the measurement is how you tell which is which.

5. The change that shipped

A PostToolUse hook on Bash|Read|Grep|Glob. It reads the transcript tail, counts tool calls per assistant turn, and prints one line when four turns in a row have each carried a single call, then stays quiet until the next multiple of four. A batched turn clears the run.

Proved against known answers before being trusted

3 singles        -> quiet     (expected quiet)
4 singles        -> FIRED     (expected fire)
5 singles        -> quiet     (expected quiet, between thresholds)
8 singles        -> FIRED     (expected fire)
4 then batched   -> quiet     (expected quiet)

malformed stdin  -> exit 0
empty payload    -> exit 0
missing file     -> exit 0

It never blocks a tool call: every error path returns zero. Against this live session it stays quiet, because the turns leading up to it did batch, which is the behaviour it is meant to reward.
