Nostalgia Live Sets

Every Zero-G Nostalgia preset installed into a ready-to-play Ableton Live 11 Set. Ten instruments to a pitched set, five racks to a drum set. Built 2026-11-12 on Jacks-iMac against Live 11.3.43, which loaded every preset itself. Sets live in ~/Music/Ableton/Nostalgia Live Sets/.

Live did the loading, addressed by path

Each set starts as an empty Live Set written at its final path, so the save needs no dialog. Live opens it, a MIDI track goes in for each preset, the preset file is handed to Live by absolute path, and one Cmd+S saves the set at that same path. All 55 sets on this page were written by Live 11.3.43 that way.

The path matters because Live's browser search cannot reach these presets. All 209 pitched families ship twice under the same file name, once as a Simpler in Nostalgia Multisamples and once as a Sampler twin in its Sampler subfolder. A probe asked the browser for five Simpler names and got five Sampler twins back, two of them the same wrong preset, because the search for Nostalgia 303Growler also matches Nostalgia 303Growler Stab and the shorter name sorts second. Handing Live open -a Live <file>.adv loads that exact file onto the selected track, and the read-back check then compares every track name against its preset and every device root against the flavour the source folder calls for.

Drum racks need Live for a second reason. A .adg stores its pads as BranchPresets, a different shape from the Branches a loaded rack has inside a set, and only Live performs that conversion.

Live opened every one

All 55 sets were opened in Live 11.3.43, one at a time, after the build. Each was checked three ways: Live's window title carried the set's name, Live's own log recorded Loading document for that exact path, and the log between the request and the load held no error:, no corrupt and no PointeeId line. 55 of 55 passed all three. The ledger stores each set's size and modification time beside the result, so a set rewritten later is opened again rather than counted on its old entry.

What the XML route taught, before Live took over

The first build wrote the pitched sets straight into the set's XML, since a Live Set and a .adv preset store an instrument identically. Of the 1,635 lines in a Sampler device, 1,612 copy through untouched. That route is retired for the shipped sets, and three of its findings are worth keeping.

Live rejected the first generated set. It drew “the document is corrupt (non-unique Pointee IDs)” and its log printed the five offenders, PointeeId 23286 through 23290, each used twice. The renumbering had taken its starting point from the three tags it was rewriting, and those five ids belonged to VolumeModulationTarget and its siblings in the track mixers, which it never looked at. The shared id space is the automation and modulation target family alone: inside a set Live wrote, 18 ids are shared across tags, every one of them pairing a structural tag against a target tag, and no two members of the target family share an id.
The two routes were compared on the same five presets. One batch was rebuilt by hand through Live, five presets loaded onto tracks from the browser and saved with Cmd+S, then diffed against the generated file. Same element tree on all five devices. Of 2,385 value paths compared, 25 differ, and every one is Live rewriting a float through its engine, 50 as 50.0000153, 1200 as 1200.00037.
That diff found the field the generator left blank, BrowserContentPath, which Live fills with query:Find#FileId_NNNNNN. The number is the preset's row id in Live's own browser index, a WAL-mode SQLite database that has to be copied with its -wal companion or recent writes stay invisible. All 486 presets resolved to exactly one id each, and the derived values matched 10 of 10 that Live had written.

A checksum claim this page used to make

An earlier version of this page said a zero OriginalCrc meant a defective file. Two corrections followed. First the algorithm was found, after an earlier build had called it uncomputable: CRC-16, polynomial 0x8005, init 0, not reflected, over the first 16384 bytes, which reproduces all 46 checksums in the template set. Then Live itself wrote every set on this page, and its own output carries 3,092 zeros among 10,076 OriginalCrc values. A zero there is Live's own behaviour. The sweep runs the check that decides whether a sample will play: every sample path in every set exists on disk and is larger than zero bytes.

Where a number comes from

  • Instrument, pad and sample counts are read back out of each saved .als with ElementTree, rather than from what a builder believed it wrote.
  • Drum rack and pad counts are counted in the file Live saved, so they measure Live's conversion rather than the preset.
  • Every sample path in every set was checked to exist on disk and to be larger than zero bytes. The 4,107 sample references counted here are distinct within their own set.
  • Coverage is checked across the whole collection on the pair of folder and preset name, so the Simpler and Sampler twins of one family count as two: 486 presets on disk, 486 on a track, 0 never placed, 0 placed twice.
  • Live's own log was read after each set was built, and again after opening every one of the 55 finished sets.

Honest limits

Sample paths are absolute, so the Black drive has to be mounted. Each set carries Live's default empty audio tracks and return tracks beside its instruments. Nothing on this page was auditioned, and no set has been played.
