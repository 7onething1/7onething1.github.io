How a set gets built

Two routes, because the two kinds of preset are not the same shape.

Pitched presets are written straight into the set's XML. A Live Set and a .adv preset store an instrument identically, so the transformation was taken from a set Live had written: the device root gains Id="0", the automation and modulation targets are renumbered, the preset reference is pointed at the file it came from, and the sample sizes are filled in from disk. Of the 1,635 lines in a Sampler device, 1,612 copy through untouched, and the generated file matches Live's own line for line.

Drum racks cannot be. A .adg stores its pads as BranchPresets, which is a different shape from the Branches a loaded rack has in a set, so Live performs that conversion. Each drum set was written out empty at its final path first, so Live could open it with a path attached and a plain Cmd+S would write in place. That sidesteps the Save As dialog, which is the one step that failed.

What Live said

The first generated set was rejected. Live drew “the document is corrupt (non-unique Pointee IDs)” and its log printed the five offenders: PointeeId 23286 through 23290, each used twice. The renumbering had taken its starting point from the three tags it was rewriting, and those five ids belonged to VolumeModulationTarget and its siblings in the track mixers, which it never looked at.
The id space was then taken from Live's own file rather than guessed. Eighteen ids are shared across tags inside a set Live wrote, and every one of them pairs a structural tag against a target tag, and no two members of the target family share an id. So the shared space is the automation and modulation target family alone. The corrected check passes the set Live accepts and fails the set Live rejected, which is the test it had to survive before any of these were written.

Where a number comes from

  • Instrument and sample counts are read back out of each saved .als with ElementTree, rather than from what the builder believed it wrote.
  • Drum rack and pad counts are counted in the file Live saved, after Live loaded the rack, so they measure Live's conversion rather than the preset.
  • Every sample path in every set was checked to exist on disk.
  • Live's own log was read after each drum set for load errors.

Honest limits

OriginalCrc is written as 0. Live stores a checksum beside each sample reference and it did not match any of 24 CRC-16 and zlib variants tried over six byte spans of a sample whose true value Live had written. Zero is Live's own value for unknown and it is what the source presets carry. Live fills in the real checksum the first time it saves the set. A number invented to fill that field would be a false statement about the sample on disk.

Sample paths are absolute, so the Black drive has to be mounted. Each set carries Live's default empty audio tracks and return tracks alongside its five instruments. Nothing was auditioned.
