How "don't use much" was measured. Spotlight's kMDItemLastUsedDate came back empty for every app in /Applications, so it could not carry the ranking. The number in every row below is the newest modification time across that app's ~/Library/Preferences/<bundle-id>.plist, its Saved Application State, its Containers, its Caches, and its HTTPStorages folder. That is a proxy for a launch log. An app that writes preferences on a background timer will read fresher than your real usage, and an app that never writes will read staler.

Nothing was deleted

All 17 application bundles were checked on disk after the edit and every one is still present. Removing a Dock icon changes a preferences key. It does not touch the application, so Launchpad and Spotlight still open every app in the removed table.

Restore

The plist was backed up before the first edit. Restoring it puts back exactly these 17 icons, in their original order and positions: SoulseekQt (disk image), Google Chrome, Google Chrome, SoulseekQt, Waves Central, Kindle, Bear, Automator, inMusic Software Center, Preview, QuickTime Player, Safari, Phone, Notes, Screen Sharing, Canva, TextEdit. The 20 kept icons are unaffected by the restore.

cp ~/.claude/backups/dock/com.apple.dock.plist.20260908-111610.bak \
   ~/Library/Preferences/com.apple.dock.plist && killall cfprefsd Dock

Method

The edit was written through CFPreferences so the preferences daemon could not overwrite it, then the Dock was restarted. Editing the plist file directly is the way this silently reverts.

# dry run, prints the plan and writes nothing
/usr/bin/python3 ~/.claude/backups/dock/dock_prune.py --dedupe --broken --dry-run

# drop dead icons and repeat entries
/usr/bin/python3 ~/.claude/backups/dock/dock_prune.py --dedupe --broken

# drop named icons
/usr/bin/python3 ~/.claude/backups/dock/dock_prune.py --label "Safari" --label "Preview"
