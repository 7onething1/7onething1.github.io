2. The continuation controller

Claude Code holds the queue and decides what to send. The browser sessions do the work. That is the difference between a feedback loop and a prompt loop.

What it does on each tick

Working
  • Reads the real state of every registered conversation through Chrome's DOM, with no API calls and no cost.
  • Writes a verified checkpoint whenever the conversation changes, holding the tail actually observed plus the queue as it stood.
  • Composes the next instruction from the queue and that checkpoint. The instruction states the last completed step, what remains, and the single next action.
  • Refuses to send during a streaming response, on any state it cannot classify, when another target has already been sent to this tick, and inside the minimum gap.
  • Marks a target blocked after three nudges with no progress, or at once on a platform blocker such as a conversation length limit.

The word continue appears nowhere in anything it sends.

5. The lyrics problem

The lyrics problem is a transport problem wearing a copyright costume. Asking a model to retype protected text is both the thing it should refuse and the slowest possible courier. The two jobs are now separate.

Exact text moves locally, AI works on features

Built

Transport. Embedded lyric frames in files you own, .lrc sidecars, JSON packs already on disk, and your own clipboard through capture_clip.py. Byte for byte, with no model in the path. Every row carries source, source_ref and rights_note, so the Joni pack's own "personal, non-commercial study only" note survived import rather than being dropped.

Intelligence. features --out emits hashes, counts, structure and quality flags with no lyric text in it. That is enough for identification, matching, indexing, deduplication and quality checking.

Loaded today from material already on your disk: 33 songs, 22 rows from JSON packs, 10 from .lrc sidecars, 1 from an embedded tag.

Export tested against every line over 12 characters in the database: 0 verbatim lines leaked in 15,060 bytes

What the quality pass caught on real data

Verified
  • 3 rows carry invisible unicode. Two Beach House lyrics hold U+2005 and one holds U+205F. These are the exact characters your voice gate hunts, and they are invisible in every editor you would open them in.
  • 1 row is not a song. A Chipperish Media podcast episode at 151 characters was flagged as suspiciously short, correctly, because its lyrics tag is not a lyric.
  • 0 duplicates in the current corpus. Duplicates get marked, never removed.

6. The rigor dial, read from Game-Studios

The transferable piece from that repository, which is why it was on the 23 October page at all.

One dial fronting six settings

Read

The repository carries 18 hooks. The part worth taking is modes.rigor, a single setting whose whole job is to expand into six knobs: modes.review_mode, modes.workflow, docs.density, qa.level, modes.story_granularity and team.size. Its own config file warns that seeding any of the six pins that value and shadows the expansion, so the dial stops changing anything.

Your honesty gate has no such dial. Six hooks fire at full strength on every turn, whether the turn is a one-line edit or a shipped chapter. A rigor setting that expanded into which gates run would cost nothing and is the one idea in that repository worth having.

8. Second pass, run after the work was finished

An independent re-examination, looking for what the first pass missed and challenging what it had already concluded. Four findings, two of them real defects that were still live.

The sandbox upgrade is a regression on this machine

Reverted

The 23 October page scored the Bash sandbox 9 out of 10, and the reasoning was sound: it replaces bypass mode with a real boundary. I enabled it with your actual write paths.

It took effect immediately and turned off Apple Events. osascript to Chrome began failing with -600 with Chrome demonstrably running, which breaks the continuation controller's in-session bridge and your auto-open-deliverables gate, since open -R and launching Firefox both go through Launch Services.

A change that breaks two standing gates fails its own test. It is configured, tuned and switched off, with the reason written into the settings file. The launchd controller is unaffected because it runs outside this sandbox. For a single hardened session: claude --settings '{"sandbox":{"enabled":true}}'

Confirmed by testing before and after: -600 with sandbox on, 1 window with it off

The doctor command was misreporting permission

Fixed

It reported Automation permission: GRANTED because it inherits the grant of whatever shell invokes it. The launchd job runs as a different responsible process and holds no such grant, which is the entire reason the scheduled run hung. A health check that passes while the thing it checks is broken is worse than no check.

It now states that caveat and prints the launchd job's own last tick outcome.

The step-closing marker was still vulnerable

Fixed

Defect 8 in the table above surfaced on this pass. The first pass had concluded it was safe because the controller's prompt is a single line that starts with a bracket. That is luck rather than a guard, and a direct test proved a line beginning EVIDENCE: would close a step with my own instruction text as its evidence.

One stall marker is too broad

Noted

please try again is in the stall marker list and could appear in ordinary model prose. The consequence is mild, since both stalled and idle lead to the same action, and it is recorded here rather than quietly left.
