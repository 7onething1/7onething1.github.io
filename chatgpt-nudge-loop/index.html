ChatGPT Nudge Loop

Every ten minutes, a launchd job types one audit instruction into a ChatGPT conversation in Chrome and presses Send. No tokens, no Claude session needed.

Why the rotation exists. One identical sentence sent fifty times makes ChatGPT restate its last answer. Each fire takes the next angle in the list, so the loop keeps asking a different question of the same work. The counter sits at 12, so the next fire sends angle 5.

The ten-minute instruction, in rotation

  1. 1/8
    fix anything else that's wrong, and search online where you have questions.
  2. 2/8
    fix anything else that's wrong. This pass, re-check every parameter value against the manual's actual range for that control, and list any you cannot source.
  3. 3/8
    fix anything else that's wrong. This pass, audit slot assignment and ordering end to end, and name every slot whose mapping you cannot verify.
  4. 4/8
    fix anything else that's wrong. This pass, verify every claimed amp and effect model name against Mooer's own documentation, and flag each one you inferred.
  5. 5/8 ← next
    fix anything else that's wrong. This pass, attack the file format itself: schema, encoding, byte layout, and whether the pedal would actually accept the pack.
  6. 6/8
    fix anything else that's wrong. This pass, find what the regression suite does not cover, then add the missing checks and show them failing before they pass.
  7. 7/8
    fix anything else that's wrong. This pass, reconcile the handoff document against the shipped pack and fix every place they disagree.
  8. 8/8
    fix anything else that's wrong, and search online where you have questions. If you have run out of defects you can verify without hardware, say so plainly in one line and then re-audit your three least-certain claims instead of restating the hardware caveat.

Targets, in order

Why there is a list. A ChatGPT conversation eventually refuses new messages with "you have reached the maximum length for this conversation." The first build of this job pointed at one thread, that thread filled up, and the job logged 90 failures in a day while still exiting 0, so launchd read a healthy service. Now a maxed thread is recorded dead and the job walks to the next id in the list.
