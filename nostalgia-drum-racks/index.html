Pad layout

White keys from C1, which is the standing convention here rather than GM, and it lines up with Ableton's own computer-keyboard row at octave 1, so A S D F G play the first five pads. Live stores the receiving note as 128 - MIDI.

Remaining roles run chromatically from A1 in one fixed order across every rack, so the layout stays predictable. A role with no sample in a family gets no pad, and no gap is padded with a duplicate. The 29 files set aside

A file counts as a pattern loop when the skill's own onset detector reports 5 or more onsets. The threshold was calibrated against both populations rather than assumed: 12 named patterns run 5 to 13 onsets, a 120-file sample of real one-shots runs 0 to 4, and 5 misclassifies none of the 132. The naive rule of one onset would have discarded 23 of those 120, because 808 Kick_long is a single hit whose pitch sweep trips a second peak. Duration alone separates nothing, since crashes and long kicks both run past a second, and a filename rule misses the twelve Rhythm Ace LP loops entirely, since LP is indistinguishable from a machine name.

What is inherited and what is unknown

Each rack is a clone of the vendored Live 11.3.30 template, since a hand-rolled preset is rejected by Live and the template's own inner ids repeat across its branches, so only the top-level branch id needed renumbering. The inert warp markers, slice points and onset events come with it, along with a stray path to the rack it was first saved from. Those are left alone.

Pad order inside a role comes from a naming rule. No sample was auditioned, nothing was sliced, levelled or modified, and nothing was deleted. The library peaks at or near full scale, which is Zero-G's mastering, so no re-levelling was warranted or performed.
