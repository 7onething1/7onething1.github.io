1. The ask, in Brandon's words

“H made 1 through 55 presets, which turns out being 37 A through 50 D. Look at what that has and what would be best for me, and let’s make presets for 1A through 36D, so we have a full complement of sounds. Learn from the mistakes of the other chat, which is, like, not setting all of the various parameters and using a variety of clean and dirt and fuzz and speakers, and, like, really utilizing all the possible settings to find the sound that matches the name.”
gpt-preset-library-design, turn 1, verbatim

Three separate requirements live in that sentence:

1. Fill the slots

144 presets into 01A–36D, preserving the audited 55 at 37B–50D.

2. Set all the parameters

The named failure of the prior pass. This is the requirement the validation found broken again.

3. Real variety

Clean, dirt, fuzz and speakers, so the sound matches the preset name.

2. Phase 0: a live conflict over the same slots

the decision this plan takes

A queued item asks to resume that run from 01C through 37A. Resuming it works against the ask. Cycling the same 55 presets across 144 slots yields 144 slots holding 55 distinct sounds, which is the opposite of “a full complement of sounds” and of the variety of clean, dirt, fuzz and speakers that was asked for.

So: the 144 design supersedes the cycling fill for 01A through 36D. The cycling run stays available for any slot the design does not cover, which right now is 37A alone. Two slots need unwinding, 01A and 01B, and the material to unwind them exists.

why a wrong name is not cosmetic

The how-to doc records that a block carrying wrong or missing parameter names is silently rejected and replaced with the pedal’s own defaults. A chorus specified at MIX 8 once ran at MIX 50, with exit codes, dialogs and file contents all looking fine. A misspelled model does not fail loudly. It just plays something else.

7. The three phases

Phase 1

Make the design installable. Desk work, no pedal, no risk.

  1. Apply the 14 resolved aliases. Record the 3 judgment calls with their XML evidence, then apply them.
  2. Build the parameter translation table chain by chain, from the XML rather than from the prose labels. EQ carries the dB plus 16 encoding, so a flat band is 16.
  3. Fill the four CAB parameters for all 139 CAB rows. This is real design work with a stated rationale per preset, since speaker, mic and distance are part of matching sound to name.
  4. Resolve the NS GATE mismatch, which is a model choice. A preset that wants RELEASE needs 03: NOISE GATE.
  5. Re-run the validator until bad-model is 0 and bad-param is 0.
  6. Harden the validator so its range check cannot pass vacuously. It must assert that resolved parameter names equal parameters present, and hard-fail when a row contributes nothing.
Done when: 0 bad models, 0 bad parameters, a non-zero count of range comparisons actually performed, and every one of them in range.
Phase 2

Emit .mo files and gate them, one bank at a time.

  1. Write the emitter from design rows to .mo JSON, nine effectModule keys "0" through "8", canonical bytes json.dumps(d, indent=4, sort_keys=True, ensure_ascii=False) + "\n".
  2. Enforce both filename rules: filename equals fileInfo.preset_name exactly, and names truncate to 16 characters on the pedal. Any design name over 16 gets shortened at the source, so a readback cannot report a false MATCH against an untruncated name.
  3. Diff every emitted block against a factory preset using the same model, to catch a parameter set the pedal would silently reject.
  4. Work one bank of four at a time, 36 banks. Never a bulk pass.
Done when: 144 .mo files exist, each filename matches its internal name, and each block’s parameter set matches the model table exactly.
Phase 3

Write to hardware and prove it.

  1. Extract the backup per slot. The 2026-11-02 device backup already covers all 144 target slots, so the archive exists. Split it into per-slot .mo files using the offsets in GE150PRO-preset-list-2026-11-02.tsv, so one slot can be restored without replaying the whole device image. Restore 01A and 01B from it, since the cycling run overwrote them with duplicates.
  2. Confirm 37A. The old audit starts at 37B, so 37A’s occupant is unknown and is not assumed free. 37A is also the one slot the cycling run may still own, since the 144 design does not reach it.
  3. Per bank: v4_probe.sh, then v4_write.sh with a mapping built from the probe screenshot, then v4_readback.sh, then sha256 against the master.
  4. Carry the known traps: window-relative coordinates re-read before every drag, float math through python, caffeinate inside the batch, the list_fingerprint.py scroll detector at threshold 97, a fresh mtime as the only witness that bytes came off the device, and the frontmost-process check.
  5. Expect Dual Delay TIME B to read back 40 ms above what was written, and do not write readback files back.
  6. Write all 144, read back all 144, compare all 144. A sample is not proof. The prior pass recorded 9 of 12 tape presets still on the wrong reverb type while a single readback was cited as evidence.
Done when: 144 written, 144 read back, and every mismatch is either sha256-identical or explained by the documented TIME B read-path offset.

9. The CAB block, filled

Done 2026-11-08, the largest remaining gap. Of 144 CAB blocks, not one set any of the four controls the pedal gives you. All 144 carried CAB=<the cabinet name again> and SOURCE=built-in factory cab, which restates the model and sets nothing.

the discovery that made this worth doing

TUBE and MIC are enumerated selectors, not numbers. The XML holds their option lists in the range field, which my earlier validator read as a numeric min and max and therefore skipped entirely.

So the CAB block is a power tube, a microphone and its placement. The design set none of it. Decoding the reference pack confirms the reading and shows its author knew the gear: 6V6 on a Deluxe cab, EL34 on a 1960, EL84 on a UK 212, and TUBE=OFF on the JAZZ 212, correct because a JC-120 is solid state.

ON-only. A switched-off block stores factory defaults. The control test earned its keep

Running the new pack gate against two known-good packs found three bugs and one real defect in the reference pack. The 55 already on the pedal passed clean.

a real defect in the reference pack

All 10 files are named 01 Eterna Choir.mo while their preset_name is Eterna Choir. The how-to doc records the consequence: the COMPUTER list silently refuses any file whose name differs from fileInfo.preset_name. The pack's README says to drag them in, and as shipped they would be refused with no error. Fixed copies are in refpack-importable/, which passes the gate at 10 files and 359 checks. The originals are untouched.

a bug in my own filler, and the rule that fixes it

I had been treating EQ and PITCH as two separate encodings. They are one rule: stored = (displayed − min) / step. EQ bands have min −16 and step 1, so stored is dB plus 16. PITCH SHIFT has min −12 and step 0.1, so +12 semitones stores as 240. Every other parameter has min 0 and step 1, where stored equals displayed. Exactly 19 parameter definitions are affected.

My filler clamped stored values against the displayed range, which silently destroyed the encoding on 10 presets:

IntentWas storedWhich decodes toNow
PITCH SHIFT +1212−10.8 semitones, nearly an octave down240, +12.0
DETUNE0−20.0 semitones280, +8.0

An octave-up shimmer would have played nearly an octave down. Nothing in the workbook looked wrong, because 12 is a plausible number for a control whose displayed range is −12 to 12.

two contamination problems, found and closed

My own output had entered the evidence. The donor roots included the directory this pass writes, so after the first emit, re-mining counted 6 of my own emitted DETUNE blocks as 6 independent observations. That is this pass's inferences becoming the next pass's evidence. The miners now exclude generated output and retired delete/ folders, leaving 361 genuinely independent files.

A known invented value was being averaged in. The how-to doc records a converter special case that wrote an invented PITCH: 0.1; two blocks carry it and it was pulling the DETUNE median toward zero. The miner now drops it by name. With it gone the only real evidence is the pack at stored 280, which is +8.0 and matches its README, corroborated by factory 65 Deluxe at 275. That rests on n=1 and is tagged as such.

the expression block

All 277 presets already written to this pedal carry one identical Exp block, MODULE_CTRL 0, PARA_CTRL 0. That is an untouched default, so the 55 on the pedal have no real expression assignment despite the V25 document recording a policy per slot. For the 144 the emitter writes the chain index and the control's position in the model's parameter list, tagged INFERRED in the manifest because every observation sits at 0. All 144 mapped.

the transport is USB HID, not MIDI

The how-to doc says "There is no USB API and no file-drop import", which is true of a published API and not of the transport. The editor links two bundled libraries and calls them directly:

libusb-1.0.0.dylib   libhidapi.0.dylib

_hid_init  _hid_enumerate  _hid_open  _hid_write  _hid_read_timeout  _hid_close
_libusb_claim_interface  _libusb_bulk_transfer  _libusb_detach_kernel_driver

It contains zero references to CoreMIDI, SysEx, MIDIClient or MIDISend. Presets move over raw USB HID reports and bulk transfers against 0x0483 / 0x5703.

Why that matters. A programmatic write path exists in principle, and it would remove the synthetic-drag dependency completely: no window geometry, no row pitch, no scroll detector, no screensaver race. That is a materially better Phase 3 than driving the GUI.

What was not done. No HID was spoken to the pedal. Reverse-engineering a write protocol and exercising it on the hardware risks the device and sits far outside "write the presets we designed". It is recorded as a route to take deliberately, proved on one spare slot first, rather than improvised.

15. Brandon's review pass, and what it changed

He read the settings workbook and returned six defects. Five were real, one was my spreadsheet, and writing his reasoning down as a rule found five more.

The one that was mine. He flagged 21D, 27C and 30B for Dual Delay blocks with empty TIME and SUB-D. The presets are correct: they hold TIME A 420 and TIME B 630, and 30B holds 500 and 750. Dual Delay has no parameter called TIME, so a sheet with fixed column names printed blanks on a correct preset. Every block now prints its own parameters.

The rule his findings became. A preset named for an effect must have that block switched on, running a model that matches the name. Run across all 28 pedal presets it failed nine times:

The two Deftones presets traded places. He said the Muff at GAIN 68 contradicted the flat clean JC-120 and the delicate song it was named for, and that a clean JC with a compressor and a tri-chorus would never deliver the central riff on 25B DEFT DIAMOND EYE. The fuzz came out of 36D, and the constructed high-gain architecture moved to 25B, rebuilt on a Rectifier into an Orange 412, pairing the amp Deftones are documented on with the cab they are documented to use rather than one matched set.

He also corrected what the audit was counting. The first workbook carried 123 mic-placement and 117 cabinet suggestions and zero musical ones, which is backwards: a matched amp and cab is often right, and a low-gain 808 pushing a hot amp is a deliberate metal technique. Of the 15 stacked-gain flags, 11 run pedal GAIN 18 to 25 and are now left alone. Only four are genuinely two distortions, led by 13A TOOL AENEMA with a Muff at GAIN 81 into an amp at 55.

The repetition that does matter. His three numbers checked out and two were worse than he said. BLUE COMP is on 42 presets with 3 distinct parameter sets, 35 of them identical. EQ is on 137 presets with 11 distinct curves, the top four covering 124. ROOM is on 46 with 14 sharing one identical setting. Counting every block, 109 groups of presets share one parameter set. That is the open work.

The copied parameter sets, tuned. Every value below is derived from the preset it sits in rather than assigned from a bucket. How much compression a patch needs falls as the amp gets hotter and falls again when delay and reverb are running, because squeezing a long tail pumps it. The EQ answers what the amp model is voiced like, what size cab it is going through and how hard it is driven, after deriving it from the amp's own knobs collapsed: BASS 46 / MID 60 / TREBLE 55 / PRES 51 repeats across dozens of presets. The room answers how driven the patch is and how bright the amp is. The gate threshold tracks the noise the chain actually makes.
