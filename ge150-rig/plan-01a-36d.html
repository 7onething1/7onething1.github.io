1. The ask, in Brandon's words

“H made 1 through 55 presets, which turns out being 37 A through 50 D. Look at what that has and what would be best for me, and let’s make presets for 1A through 36D, so we have a full complement of sounds. Learn from the mistakes of the other chat, which is, like, not setting all of the various parameters and using a variety of clean and dirt and fuzz and speakers, and, like, really utilizing all the possible settings to find the sound that matches the name.”
gpt-preset-library-design, turn 1, verbatim

Three separate requirements live in that sentence:

1. Fill the slots

144 presets into 01A–36D, preserving the audited 55 at 37B–50D.

2. Set all the parameters

The named failure of the prior pass. This is the requirement the validation found broken again.

3. Real variety

Clean, dirt, fuzz and speakers, so the sound matches the preset name.

2. Phase 0: a live conflict over the same slots

another run is writing here

overwrite_factory.py carries this docstring: “Overwrite 01A..37A with our 55, in rig-page order, cycling.” Its overwrite_order.json is the list of the 55 audited names. overwrite_log.txt records how far it got:

  1 01A CAP MULTI C OK
  2 01B CAP MULTI B OK
RUN END
ABORT 01C CAP MULTI A: selection moved 223.25->580.25, list scrolled or write off row

01A and 01B now hold copies of 37B and 37C. The run stopped at 01C when the scroll detector caught the preset list moving, which is the guard working exactly as the how-to doc describes.

the decision this plan takes

A queued item asks to resume that run from 01C through 37A. Resuming it works against the ask. Cycling the same 55 presets across 144 slots yields 144 slots holding 55 distinct sounds, which is the opposite of “a full complement of sounds” and of the variety of clean, dirt, fuzz and speakers that was asked for.

So: the 144 design supersedes the cycling fill for 01A through 36D. The cycling run stays available for any slot the design does not cover, which right now is 37A alone. Two slots need unwinding, 01A and 01B, and the material to unwind them exists.

why a wrong name is not cosmetic

The how-to doc records that a block carrying wrong or missing parameter names is silently rejected and replaced with the pedal’s own defaults. A chorus specified at MIX 8 once ran at MIX 50, with exit codes, dialogs and file contents all looking fine. A misspelled model does not fail loudly. It just plays something else.

the finding that answers requirement 2

Of 139 CAB rows, not one sets TUBE, MIC, CENTER or DISTANCE. The four controls that shape the speaker are untouched across all 144 presets. That is precisely the “not setting all of the various parameters” mistake Brandon asked to avoid repeating, reappearing inside the document meant to fix it. Speaker variety was named in the ask, and the speaker controls are the ones left blank.

7. The three phases

Phase 1

Make the design installable. Desk work, no pedal, no risk.

  1. Apply the 14 resolved aliases. Record the 3 judgment calls with their XML evidence, then apply them.
  2. Build the parameter translation table chain by chain, from the XML rather than from the prose labels. EQ carries the dB plus 16 encoding, so a flat band is 16.
  3. Fill the four CAB parameters for all 139 CAB rows. This is real design work with a stated rationale per preset, since speaker, mic and distance are part of matching sound to name.
  4. Resolve the NS GATE mismatch, which is a model choice. A preset that wants RELEASE needs 03: NOISE GATE.
  5. Re-run the validator until bad-model is 0 and bad-param is 0.
  6. Harden the validator so its range check cannot pass vacuously. It must assert that resolved parameter names equal parameters present, and hard-fail when a row contributes nothing.
Done when: 0 bad models, 0 bad parameters, a non-zero count of range comparisons actually performed, and every one of them in range.
Phase 2

Emit .mo files and gate them, one bank at a time.

  1. Write the emitter from design rows to .mo JSON, nine effectModule keys "0" through "8", canonical bytes json.dumps(d, indent=4, sort_keys=True, ensure_ascii=False) + "\n".
  2. Enforce both filename rules: filename equals fileInfo.preset_name exactly, and names truncate to 16 characters on the pedal. Any design name over 16 gets shortened at the source, so a readback cannot report a false MATCH against an untruncated name.
  3. Diff every emitted block against a factory preset using the same model, to catch a parameter set the pedal would silently reject.
  4. Work one bank of four at a time, 36 banks. Never a bulk pass.
Done when: 144 .mo files exist, each filename matches its internal name, and each block’s parameter set matches the model table exactly.
Phase 3

Write to hardware and prove it.

  1. Extract the backup per slot. The 2026-11-02 device backup already covers all 144 target slots, so the archive exists. Split it into per-slot .mo files using the offsets in GE150PRO-preset-list-2026-11-02.tsv, so one slot can be restored without replaying the whole device image. Restore 01A and 01B from it, since the cycling run overwrote them with duplicates.
  2. Confirm 37A. The old audit starts at 37B, so 37A’s occupant is unknown and is not assumed free. 37A is also the one slot the cycling run may still own, since the 144 design does not reach it.
  3. Per bank: v4_probe.sh, then v4_write.sh with a mapping built from the probe screenshot, then v4_readback.sh, then sha256 against the master.
  4. Carry the known traps: window-relative coordinates re-read before every drag, float math through python, caffeinate inside the batch, the list_fingerprint.py scroll detector at threshold 97, a fresh mtime as the only witness that bytes came off the device, and the frontmost-process check.
  5. Expect Dual Delay TIME B to read back 40 ms above what was written, and do not write readback files back.
  6. Write all 144, read back all 144, compare all 144. A sample is not proof. The prior pass recorded 9 of 12 tape presets still on the wrong reverb type while a single readback was cited as evidence.
Done when: 144 written, 144 read back, and every mismatch is either sha256-identical or explained by the documented TIME B read-path offset.

8. The reverb block, finished

Done 2026-11-06. It matters beyond reverb, because it settles how the remaining 1,868 parameter mismatches get resolved: by mining real preset files rather than authoring values.

a donor corpus already exists on this Mac

mine_reverb_donors.py read 393 real .mo files, zero unreadable: the presets written to the pedal, the reference pack, the backups, a factory-baseline set, and the GE150PRO editor's own library folder. For each reverb model it produced observed min, median and max with the source file for each value. The same corpus can supply real values for DS/OD, MOD, DELAY, FX/COMP, NS GATE and CAB.

two encodings now documented

EQ stores dB plus 16, already known. MOD pitch stores (semitones plus the absolute minimum) times 10, derived from the reference pack and confirmed three independent ways against its README's own stated intent. That unblocks the ZEP KASHMIR detune the how-to doc left switched off for want of a number.

an envelope needs enough observations to bind

SHIMMER has 2 observations, and its LEVEL envelope is the single value 55 seen twice. Treating that as a constraint would pin every shimmer preset to a showcase level. The rule used a binding threshold of 10 observations. Zero authored values violate a binding envelope. Nine sit outside a non-binding one, on CHURCH and SHIMMER, and are named rather than hidden.

The biggest remaining cluster, 14 clean presets on a neutral small room, is left alone deliberately. Splitting it further would be gaming the measure.

new finding, unresolved

33 of the design's own DECAY and LEVEL values sit outside a binding observed envelope, untouched by this pass. The worst are SPRING DECAY=20 on 14 presets where 107 real springs span 21 to 62, and CAVE DECAY=73 on 4 presets where 12 real caves span 35 to 64. They are legal values, since all sit inside the pedal's declared range. No real preset on this Mac is set that way, so this wants an ear rather than a silent correction.

9. The CAB block, filled

Done 2026-11-08, the largest remaining gap. Of 144 CAB blocks, not one set any of the four controls the pedal gives you. All 144 carried CAB=<the cabinet name again> and SOURCE=built-in factory cab, which restates the model and sets nothing.

the discovery that made this worth doing

TUBE and MIC are enumerated selectors, not numbers. The XML holds their option lists in the range field, which my earlier validator read as a numeric min and max and therefore skipped entirely.

ControlRaw range fieldMeans
TUBEOFF_EL34_EL84_6L6_6V65 power-tube options
MICSM57_U47_U87_NT1_MD421_MD441_MXL2001_MXL2003_C3000_C4000B10 microphones
CENTER / DISTANCE0_100_1_0_mic placement, 0 to 100

So the CAB block is a power tube, a microphone and its placement. The design set none of it. Decoding the reference pack confirms the reading and shows its author knew the gear: 6V6 on a Deluxe cab, EL34 on a 1960, EL84 on a UK 212, and TUBE=OFF on the JAZZ 212, correct because a JC-120 is solid state.

Grounding, from the same 393 files

The corpus gives a clean modal power tube per cabinet and it matches the real gear: HWT 412 EL34 on 33 of 33, PV 5050 412 EL34 on 16 of 16, UK 212 EL84 on 13 of 15, JAZZ 212 OFF on 13 of 15, US DLX 112 6V6 on 11 of 15. TUBE is a property of the amp's power section, so it is not varied per preset. Varying it by slot would be wrong, not creative.

nine cabinets had no observation

Each was inferred from an observed sibling or from the real power section of the amp the design pairs it with, and every such row is tagged FAMILY-INFERRED in the workbook rather than passed off as observed. For example CITRUS 212 takes EL84 from CITRUS 412, EV 5050 412 takes EL34 from PV 5050 412 at 16 of 16, and ACOUSTIC112 takes OFF because an acoustic model has no power section.

a correction to my own first pass

My first mic rule made U47 the default for clean and edge presets on combo cabinets, putting it on 59 presets when the corpus uses it twice. That inverted the evidence. Rewritten so the spread mirrors the observed shape: SM57 went from 37 to 99, U47 from 59 to 2.

the reverb outliers are reconciled too

The 33 values flagged as outside a binding observed envelope are closed, across 30 rows, each moved by the smallest amount that brings it inside what a real preset has been seen to hold: SPRING DECAY 20 to 21 on 14 presets against 107 real springs, ROOM LEVEL 3 to 8 on 6, CAVE DECAY 73 to 64 on 4. CHURCH and SHIMMER were left alone, since an envelope of 3 and 2 observations cannot bind. Every original figure is recorded in reverb_outliers_RECONCILED.json, so any of these goes back by ear. Reverb now reports 0 values outside a binding envelope.

still open

Nothing has been heard through a guitar. Seven chains remain on prose or unverified values: FX/COMP, DS/OD, AMP, NS GATE, EQ, MOD and DELAY. AMP / MST = 50 START still sits on all 144 and DS/OD / LEVEL = MATCH TO DS BYPASS on 63. The same corpus can supply all of them by the method now proven twice. The 30 expression targets naming a control the pedal lacks are also untouched.

10. What this plan does not claim

limits, stated
  • No preset in this design has been heard through a guitar. Every statement on this page is about bytes, names and ranges.
  • The numeric targets are design proposals. The 9 BLOCK MATRIX sheet labels all 891 ON rows UNVERIFIED EDITOR VALUES, and that label is accurate.
  • The dual-pedal architecture, the second GE150 Pro and the Eventide Space routing live in the 128-turn Dual Pedal Optimization Plan thread, which is staged to disk and has not been read in full for this plan. Nothing here depends on it. Banks 35 and 36 are the ones the design assigns to dual-rig voices, so they need that thread read before they are built.
