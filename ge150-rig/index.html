1. Why the app did nothing, and the fix

Fault 1

The pedal was never on the USB bus. A full system_profiler SPUSBDataType sweep returned a Samsung T7 Shield, the Bluetooth controller, the FaceTime camera, a 2.4G receiver, and a PNY flash drive. No Mooer device, and no USB audio or MIDI interface of any kind. You confirmed this yourself, that the device had not been added yet.

Fault 2

The app that was running is the firmware updater, not the editor. The process alive on this Mac was /Applications/GE150PLUS.app/Contents/MacOS/GE150PLUSUpdate. That outer bundle has CFBundleExecutable = GE150PLUSUpdate and ships one firmware image at Firmware/GE150PLUS_V2.1.3.mr. Its only job is flashing. The preset editor is a second application nested inside it.

Fault 3

A charge-only cable will look identical to a broken app. The editor links libusb-1.0.0.dylib and libhidapi.0.dylib, so it reaches the pedal over raw USB and HID rather than over a MIDI port. It needs a true data cable on the pedal's USB editing port. With power-only wiring the pedal lights up and the editor still reports nothing attached.

Fix, in order
  1. Plug the pedal into the Mac with a data USB cable, into the pedal's USB editing port, and power the pedal on.
  2. Confirm the Mac sees it before opening anything: system_profiler SPUSBDataType | grep -i mooer. A line of output means you are clear to proceed. Silence means the cable or the port, so swap the cable first.
  3. Launch the editor, which is the nested bundle, not the outer one: 
    open "/Applications/GE150PLUS.app/Contents/MacOS/GE150PLUS.app"
    That path is already verified to launch on this Mac, process GE150PLUS under PID 28530 during this session.
  4. Keep the outer GE150PLUS.app for firmware flashing only.
  5. Back up your current device presets inside the editor before importing anything. Dragging a preset onto a DEVICE slot overwrites that slot.

The Chinese interface, and why it cannot be switched from inside

Fault 4

The updater has no language button. Its binary contains only four buttons, closButton, messageBoxButton, openFileButton and startButton. The editor is the one that carries QPushButton#languagebutton and a LanguageManager. So the Chinese window is the updater, and no amount of clicking inside it will change the language.

Both apps read /Device/CurrentLanguage out of config.ini and load either Chinese.qm or English.qm. Yours sat at CurrentLanguage=0, which is Chinese. The English file is 16 bytes, a valid but empty Qt translation, so selecting it lets the built-in English source strings show through.

Why the obvious fix fails

Editing config.ini inside /Applications/GE150PLUS.app returns Operation not permitted. That is macOS 13 App Management protection, not file permissions, since the file is -rw-r--r-- and owned by you. ~/Applications is protected the same way. Editing it in place would also break Mooer's code signature.

Fixed, and verified on screen

A copy of the bundle now lives in an ordinary folder, outside App Management's reach, with CurrentLanguage=1 set in both the updater and the nested editor, the Firefox quarantine flag cleared, and an ad-hoc signature applied so Gatekeeper accepts it.

open ~/Projects/_outputs/ge150/GE150PLUS-EN.app

Proof it worked. The relaunched app put up an English dialog reading "Error, The device is disconnected." That single screen confirms the language switch and independently confirms Fault 1, in the app's own words.

The original in /Applications was left untouched and still opens in Chinese.

Worth doing once

The bundle still carries a Firefox download quarantine flag, com.apple.quarantine: 03c1;6ae6624b;Firefox. It is correctly signed by Shenzhen MOOER Audio Co., Ltd, team ID 67DUZ7D49G, so Gatekeeper will allow it. If macOS ever refuses to open it, clear the flag with xattr -d com.apple.quarantine /Applications/GE150PLUS.app rather than reinstalling.

The .mo format, for the record

The original GE150 editor reads .mo files, and they are plain JSON rather than an opaque blob, which is the only reason this pack could be rebuilt at all. The structure is three top level keys, effectModule holding all nine blocks, Exp for expression pedal assignment, and fileInfo for the device stamp.

{"effectModule":{"FX/COMP":{"TYPE":6,"SWITCH":0,"Data":{...}},
  "DS/OD":{...},"AMP":{"TYPE":1,"SWITCH":1,"Data":{"GAIN":30,"BASS":48,
  "MID":52,"TREBLE":58,"PRES":52,"MST":78}},"CAB":{...},"NS GATE":{...},
  "EQ":{...},"MOD":{...},
  "DELAY":{"TYPE":4,"SWITCH":1,"Data":{"LEVEL":34,"SUB-D":1,"TIME":450,"FEEDBACK":38}},
  "REVERB":{"TYPE":4,"SWITCH":1,"Data":{"PRE DELAY":12,"LEVEL":22,"DECAY":38,"TONE":45}}},
 "Exp":{...},
 "fileInfo":{"app":"GE150 Edit","device":"MOOER GE150","preset_name":"CAST MARE",
  "schema":"GE150 Preset"}}

Block type numbers are zero based, so Tape is delay TYPE 4 and Spring is reverb TYPE 4.

2026-11-03 · solved, twelve presets on the pedal

Two things were wrong, and the second one is the whole story.

  • The Pro preset schema is structurally different. A genuine Pro preset, pulled off the pedal by dragging slot 33A into COMPUTER, is 2,440 bytes against our 958. Its effectModule keys are the numeric strings "0" through "8", not module names, and its fileInfo reads device: "GE150PRO", app: "GE150PRO Edit", schema: "GE150PRO Preset". Parameter names differ too: F.BACK rather than FEEDBACK, P.DELAY rather than PRE DELAY.
  • The editor requires the filename to equal preset_name. Proven with a two-file control: ZZTESTA.mo holding preset_name "ZZTESTA" appeared in the COMPUTER list. zz_test_b_file.mo holding "ZZTESTB", byte-identical otherwise, did not. The same pair of outcomes repeated with CAST MARE.mo against 01_CAST_MARE.mo. This is why every earlier import copied the file into the library and still showed nothing.
  • The COMPUTER panel is reached by right-click, not the folder icon. Its menu is Add, Delete, Refresh, Open This Directory. The folder icon only opens the library in Finder, which is where the “already exists” message came from.
  • No empty slots exist. All 200 are named, so the twelve went to 48A–50D, which the existing .backup files restore.

Two failure modes worth writing down

The screensaver eats drags. Fourteen consecutive writes reported no import dialog and nothing changed on the pedal. The cause was the 8-minute idle timer firing mid-batch: macOS composites a full-screen secure window over everything, so each drag landed on that instead of the editor, and the Mac then sat at the password prompt. A batch of GUI writes has to hold the display awake for its whole run.

caffeinate -d -i -w $$ &   # for the lifetime of the script

Signalling the screensaver process is the wrong recovery. It leaves an orphaned secure surface that WindowServer will not give up, which black-screened this Mac once before. Input dismisses a saver; a signal does not.

Estimated row positions overwrite the wrong slots. Two writes aimed at 43D and 44B landed on 41C and 42B, quietly replacing TOE GOODBYE and RUSH LIMELIGHT. Reading row centres off a screenshot by eye was accurate to about 11 points against a 27-point row pitch, close enough to hit most of the time and close enough to miss by a whole row after a scroll. The fix is to measure rather than estimate: the selected row draws a solid rgb(152,198,24) band, so scanning one pixel column for that colour gives an exact anchor, and every other row follows from the 26.9-point pitch.

ys = [y for y in range(280,1250) if px[300,y] == (152,198,24)]
centre = (ys[0] + ys[-1]) / 4          # screenshot is 2x retina
row(n) = centre + (n - anchor_index) * 26.9

Both damaged slots were restored from the measured grid, and the device list was re-read to confirm all twenty names.

2026-11-03 · the format is now extracted, not inferred

The editor carries its own parameter dictionary. The model names are not plain strings anywhere in the 32 MB binary, in any encoding, because they sit in a zlib-compressed Qt resource. Decompressing the stream at offset 13,722,184 yields 21,425 bytes of XML that defines every chain, every model, and every parameter's range.

Validation first. Nine model indices had already been read off the editor by eye. The extracted table agrees with all nine: 65 US TW 1, PV 5050 DS 36, CAROL CL 40, 808 1, GOLD CLON 19, TAPE 3, SPRING 4, PV 5050 412 18, ANA-CHORUS 11.

  • 210 models across 9 chains, with 139 parameter definitions: 75 amps, 46 cabs, 28 drives, 25 mods, 12 comps, 9 delays, 8 reverbs, 4 EQs, 3 gates.
  • The SUB-D enum, which had been a guess: OFF, 1/4, 1/4T, 1/4D, 1/8, 1/8T, 1/8D, 1/16, 1/16T, 1/16D, indexed 0 through 9.
  • Ranges: delay LEVEL and F.BACK are 0 to 100, TIME is 40 to 2500 ms, reverb P.DELAY is 0 to 500, EQ bands run -16 to +16 dB with step 1 and default 0.
  • DUAL DELAY does not have a TIME field. It uses TIME A, SUB A, TIME B and SUB B.

It immediately caught six wrong files. Three El Capistan Fixed presets had no subdivision set, and the three Multi presets were written with a TIME field that Dual Delay does not accept. All six were rebuilt against the extracted definitions and re-verified in the COMPUTER list.
