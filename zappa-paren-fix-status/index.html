Corrections to the 2026-08-30 audit record

Three claims restated

  1. "Delivered, live and verified" was wrong. The correct state is submitted and pending moderation. Reading the published-revision endpoint takes one request and was not done before that header was written. The body of the same document did say "Both submitted for Songsterr moderation," so the document contradicted itself.
  2. "notes=1574 BRACKETS=0 DOTS=32 TIES=0" is the census of Zomby Woof track 9, Ralph Humphrey. It was presented as a file-level figure. The file holds 7,479 notes, and at file level the fix revision reads ghost 0, staccato 170, ties 431.
  3. "BRACKETS=0 DOTS=317" for Montana is true of the two drum staves and false of the file. The file keeps 257 brackets on non-drum staves, which is correct for a drums-only scope. DOTS 317 is the delta added. The total is 578.

The artefact these controls exposed

The same grid against the same audio scored z −1.37 under linear mapping and z +81.97 after warping. Nothing changed but the warp. A z of +82 would normally mean overwhelming confirmation. Here it is an artefact of bending the grid onto whatever energy it finds.

Root cause: drum onsets are dense and near-periodic, so any two rock drum recordings agree about equally well. A chroma measure on the same files with the same controls passed at 0.8146 against 0.6561, which places the failure in the drum-only material rather than in the method.

Verify it yourself

Every number on this page comes from these three public endpoints. No authentication is needed.

# which revision does the public actually get
curl -s https://www.songsterr.com/api/meta/35870  | python3 -c "import json,sys;d=json.load(sys.stdin);print(d['revisionId'],d['author']['name'])"
curl -s https://www.songsterr.com/api/meta/412162 | python3 -c "import json,sys;d=json.load(sys.stdin);print(d['revisionId'],d['author']['name'])"

# the full revision list, newest first
curl -s https://www.songsterr.com/api/meta/35870/revisions

# one specific revision, which yields the CDN hash for its per-track JSON
curl -s https://www.songsterr.com/api/meta/35870/8787106

Per-track note data then reads from https://dqsljvtekg760.cloudfront.net/<songId>/<revisionId>/<image>/<track>.json, where image is the hash in that revision's meta. Brackets are the note flag ghost and dots are staccato.
