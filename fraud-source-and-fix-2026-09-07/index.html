2. The mechanism, in its own source

This is the head of the script that produced the bad board, quoted from the session transcript.

CHATS = [
{

 "last":"2026-09-07T18:49:09Z","msgs":623,"state":"done",

Two separate failures sit in those four lines.

  • The count is a literal. "msgs":623 was typed. Nothing in the script opens a transcript. The real assistant count for that chat is 193.
  • The id is invented. No file named 2d4ad288 exists in the transcript store. The string appears in exactly three places on this Mac: the session that wrote it, the loop that read it, and my audit.
The correction did not fix the architecture. The 14:23 rebuild switched to {"fid":"bf53c889","t":"13:49","n":193}, which is real. The numbers are still hardcoded. The difference is that this time the session measured first and pasted the result. Nothing structural stops the next build from regressing.

4. The one rule that makes this decidable

A transcript only ever grows. That single fact turns a fuzzy judgment into arithmetic, because the direction of an error carries its meaning.

DirectionWhat it meansSeverity
claimed below measuredthe chat kept working after the snapshotwarn
claimed above measuredgrowth cannot explain it, so it was not readhard
idle staler than mtimethe chat wrote after the snapshotwarn
idle fresher than mtimeclaiming a file moved when it did nothard

No configuration, no thresholds to tune, no judgment call. It separated the bad board from the good one on the first run.

5. The skill: claim-provenance

~/.claude/skills/claim-provenance/. Run it on any page that reports per-item numbers.

python3 ~/.claude/skills/claim-provenance/verify_claims.py <file.md>
CheckCatches
C1 orphan-idAn id-shaped token resolving to no file. Catches local_2d4ad288.
C2 ceilingA count above the physical maximum of its source. Caught all nine.
C3 repeated-valueOne value shared by three or more rows in a field that must vary. Caught 1h 20m.
C4 remeasureEvery id to count and id to idle pair, re-derived and diffed by direction.
C6 uniform-offsetEvery row wrong by the same amount, which means the build stamp is wrong rather than the data.
C6 exists because the tool lied to me first. A stale reference time produced 20 false hard fails on a board that was correct. A gate that cries wolf gets switched off, so it now recognises its own bad input and names the real build time.

It also enforces a format. A row carrying a count must name the source that proves it, and a row with a number and no id is a hard fail because nothing on that page can be re-derived.

- **Status:** X | **Idle:** 1h 13m | **Replies:** 242 | **Transcript:** `30e6208e`

6. The gate: G52

Memory says there is one gate system and never to build a second, so this went into ~/.claude/skills/fifty-gates/ as gate 52 of 52, wired to the existing Stop hook.

G52 number-without-measurement, hard, session scope. It fires when a session deploys a page of per-entity numbers whose cited sources it had not read at deploy time. The skill checks the artifact. The gate checks the order of operations, because a correct number can still be a lucky guess.

It false-fired on me twice before it was right. First it matched the word overflow.sh inside an AskUserQuestion preview I had written, and counted my own hypothetical as a real deploy. Deploy detection is now restricted to Bash commands. Second, a loose source pattern let any incidental file read count as measurement. It now requires the specific ids the page cites.

8. What this does not catch

  • Prose claims. It checked every file and they were all clean carries no number to re-derive.
  • Numbers about things outside the transcript store. Drive object counts, file sizes and link totals need their own re-derivation, which is not written.
  • A correct number reached by luck. G52 covers the ordering, and only for routes deployed through overflow.sh.
  • Any deliverable that is not a markdown page under public/.
