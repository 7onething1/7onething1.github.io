Four corrections to the proposal

1. This Mac is Intel, not Apple Silicon

uname -m returns x86_64 on macOS 13.7.8. The Apple Silicon rationale for pinning Basic Pitch to Python 3.10 does not apply here.

2. A new 3.10 Basic Pitch environment would rebuild a working one and reintroduce a crash

~/venvs/audio_midi_311 holds basic-pitch 0.4.0 on Python 3.11.15 with onnxruntime 1.23.2. The constraint on this machine is the model format. The Python version is not what breaks. Basic Pitch defaults to:

/Users/drwu/venvs/audio_midi_311/lib/python3.11/site-packages/
    basic_pitch/saved_models/icassp_2022/nmp.mlpackage

That CoreML package SIGFPEs on this Mac. nmp.onnx ships in the same directory, so no download is needed. env.sh pins BASIC_PITCH_MODEL_TYPE=onnx, and a pytest case fails if that pin is ever dropped.

3. The validator stack was installed before this session, minus one package

Python 3.13.6 at /usr/local/bin/python3 carried pyguitarpro, lxml, numpy, scipy, librosa, soundfile, audioread, mido, pretty_midi, pandas, matplotlib, pydub, and music21. Only pytest was missing, now installed at 9.1.1. Building a fresh 3.12 venv would have duplicated thirteen working packages. Demucs 4.0.1 is installed in ~/venvs/demucs on Python 3.12.13 with torch 2.2.2.

4. validate_song.py mostly exists

The gates for pitch preservation, impossible spans, string collisions, ownership, octave doubling, tuning, and candidate versus source statistics are written and tuned. Writing a second set from scratch would have thrown away the recorded regression cases. The new script is an orchestrator over them, roughly 130 lines.

What got built

Repo at ~/Music/guitar-transcription, git initialised, one commit.

A gate that cannot run reports NOT RUN

The audio gates need --stem --offset --bpm. Without a validated beat map they are skipped and printed as NOT RUN. A skipped gate is never folded into a pass.

The finding the run surfaced

The existing two staff split of this song put 585 notes on Guitar and 1 note on Guitar 2. The split ran and produced a file, and the file does almost nothing. The 42 percent hand skip and the nine ownership flags remain on the first staff. Exit zero and a written file prove only that the tool ran. Neither measures whether the output is good.

Another session is editing that same tree right now. The delivery README changed on disk mid read. Nothing here writes into ~/Projects/_outputs/APPLESEED-DELIVERY-2026-08-28/, and coordinating before any repair pass is the safe move.

On two guitar ownership for Mare Vitalis

The proposal routes through a two guitar ownership step. On this album that step was measured on 2026-08-11 and it does not separate. Both players fall within about 1 dB of each other in the stereo image where roughly 12 dB would be needed to assign a note. Ownership scored at chance across all 46 songs. The workable route is the one the corpus README describes: split an unplayable beat into two hands by register and reach, change no pitches, and treat the audio as evidence for pitch rather than for authorship.

The 87/88 octave probe

Task 2 in the corpus README: 19 bad beats hold a pitch that does not exist on a 22 fret guitar, only MIDI 87 and 88, across five songs. The suspicion is that the transcriber heard the second harmonic of a note an octave below and wrote the harmonic as the note. octave_probe.py tests that. It measures band energy at the written pitch against the band an octave below, in the guitar stem, at each note's own time.

The measure was validated before it was pointed at any music

Two synthetic signals with a known answer, run on every invocation. The probe refuses to read audio if either fails.

Every one is on string 5, the high E, at fret 23 or 24. Not one appears on any other string. Since 87 and 88 have no legal position on a 22 fret neck, the writer had nowhere to put them and fell back to arithmetic fret on the top string. That makes this one systematic fallback firing 19 times rather than 19 independent mishearings, and it points the investigation at the pitch detector rather than the fingering.

Pointing the map eleven seconds away from the music aligns slightly better than pointing it at the music. A map that cannot beat its own wrong time control does not locate notes, so the per note ratios below carry no information. The wrong time ratio control agrees: median 1.31 against 1.122 for the flagged notes.

The probe prints MAP SUSPECT and withholds the verdict. That is the gate doing its job. The existing 04_TABLES/octave_test.json shows offenders at median 2.17 against a decoy control at 1.77, which is very likely the same problem: with a broken time map, offenders and decoys measure the same thing.

What unblocks it

A validated beat map for these five songs, real offset and real tempo anchored at two musical events, rather than the score tempo at offset zero. octave_probe.py takes --offset and --bpm, so the re run costs minutes once those exist.

Beat maps, derived from the audio

beatmap_fit.py derives offset and tempo per song by cross correlating the notated onset train against the stem's onset strength envelope. It then refuses the fit unless the fitted map covers more real attacks than two controls: the same map shifted eleven seconds, and random times of the same count.

The thresholds are calibrated, not invented

The first version invented a rule and a positive control caught it. Feeding the fitter a synthetic recording built from a known map, it recovered that map to 0.1 bpm and 3 ms, and the invented rule rejected it anyway. A second attempt used the lag z score to SELECT the tempo, which preferred a compressed train and chose 246 bpm over the true 172. Selection now uses the correlation peak, which recovers the truth, and the z score is computed afterwards purely as the acceptance statistic.

Three trials, each with a positive control (the tab that made the audio) and a negative control (a different rhythm of the same density against the same audio):

lag z    positive 6.29 - 7.87    negative 2.63 - 2.77
lift     positive 1.163 - 1.366   negative 0.819 - 0.961

A fourth positive scored z 4.38, so the bar sits at z 4.0 and lift 1.08: under every positive observed, over every negative observed.

Why four refuse, and it is a finding rather than a failure

Look at the last column. These tabs carry 1.9 to 4.5 times as many note onsets as the guitar stem has detectable attacks. Barrier Islands notates 1573 onsets against 347 attacks. When a notation is that much denser than the recording, almost any alignment puts a fifth of its onsets near something, so the map cannot be told apart from a random one. Only Sentence, at 1.9x, is sparse enough to align.

That density is consistent with the two guitar merge already documented: two players written onto one staff produces roughly twice the onsets a single stem shows.

The controls, which is what makes this readable

flagged notes             median ratio  0.599
count-matched other notes median ratio  7.083
same notes, wrong time    median ratio  1.066

Ordinary notes in this file put roughly seven times more energy at the written pitch than an octave below. The flagged notes invert that, at 0.599. Pointed at the wrong time the same seven notes read 1.066, so the effect is time locked rather than a property of the spectrum at large. On the earlier broken map the flagged median was 1.122 against a wrong time control of 1.31, which is why the probe withheld the verdict then.

Reading it honestly

Four of the seven point to a note an octave below, two are ambiguous, one matches the written pitch. Since MIDI 88 cannot be played anywhere on a 22 fret guitar, the one reading at 2.835 cannot be a guitar fundamental at that pitch either; the likelier explanations are another instrument bleeding into the stem, or a partial of a different note. The majority evidence supports the harmonic hypothesis on this song, and one song is not five.

The one blocker

Guitar Pro 8 needs an admin password

The Homebrew cask ships a pkg installer, so it prompts for a password that I will not enter on your behalf. Sonic Visualiser installed cleanly because its cask is a plain app bundle. Run this yourself and doctor.py goes to zero hard failures:

brew install --cask guitar-pro

Optional, if the auxiliary conversion path is wanted: brew install --cask musescore. Keeping it away from the authoritative editing path stays correct, since conversion can drop Guitar Pro specific detail.
