2. The defect: a chord has two halves

The paren sweep r8768414 dropped both halves of one chord. It removed the <Item name="E7Msus2"> from the diagram collection on the Frank Zappa staff, and it removed the <Chord> reference from the beat at bar 3 that printed the symbol. build_restore_textsafe.py restored the first half.

Why every check passed on a broken file

  • The builder verified 'E7Msus2' in text, which an orphaned definition satisfies.
  • The builder printed the list of chord Items, which never says whether a beat references one.
  • The lane-aware set difference keys on (bar, voice, position, midi). A chord symbol carries no notes, so the diff is structurally unable to see it.

This is the standing rule feedback_gate_must_read_the_field_the_human_reads, second confirmed instance. A reader acts on the symbol printed above bar 3. No check read that.

3. The trap: Beat id 2 is shared by seven bars

GPIF deduplicates beat definitions. Beat id 2 in the restore is referenced by seven voices covering track 0, bars 3 through 9. Adding a <Chord> to that definition prints E7Msus2 above all seven bars.

The repair clones the definition into Beat id 910, adds the chord reference to the clone, and repoints the bar 3 voice alone. Verified afterward: the symbol appears on bar 3 and on no bar from 4 to 9. Tool: tools/restore_bar3_chord_ref.py.

TEXTSAFE is still the right lane

A reserialized file rewrites 1,038,175 bytes of XML and reformats whitespace throughout. An upload that alters one drum track should not carry a million bytes of incidental change. String surgery keeps the diff to what was intended.

5. The 124 rest cells, cleared

The handoff audits the restore against the live export, so it never asked whether the sweep touched tracks other than track 8. It did. 124 (track, bar) cells differ from the pre-sweep source across tracks 0, 1, 3, 4, 6 and 7.

Every one of them is a bar carrying zero notes on both sides, where the source holds one Whole rest and the export holds a Whole plus a Quarter. Those bars are 5/4. Four beats plus one beat fills the bar. The source under-filled it by a beat and Songsterr normalized it correctly.
