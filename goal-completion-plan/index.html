4. Phase 1: make the guitar goal satisfiable

Four steps, no research, one song (The Mutiny)

Every item here is blocked on writing code or running a command, not on an unanswered question. Together they take the pilot song from "measured well" to "expressible in the vocabulary the condition demands".

1.1 Implement duration and sustain agreement

written_attacks() returns duration_beats, so the data is in hand and only the comparison is missing. Compare written duration against decay-to-half-energy on the stem, through the health-gated map. Ship it with a shifted-time control like every other measure in this toolchain, and report the control beside the number whichever way the result goes.

1.2 Itemise the 795 unmatched attacks

Extraction goes through BM.apply_map(tab_t, rec_t, and the rest), the call that produces the 74.1% figure. The earlier attempt rebuilt the map with np.interp and saturated at 100%, which is the circularity trap this pipeline has hit before. Output one row per miss with staff, bar, beat, written pitch.

1.3 Classify every miss in the condition's own vocabulary

Three buckets, worded exactly as the condition words them: supported correction, unsupported change, unresolved ambiguity. On current evidence most will fall into the third bucket, and that is a legitimate result the condition accepts. It does not accept the count staying unitemised.

1.4 Persist the map and seed the ledger

python3 impossible_gate.py --init-checkpoint 08_the_mutiny/songsterr.gp

Then re-run the gate with the full flag set so comparison_basis is produced and written, which closes requirements 9 and 10 at once:

python3 ~/.claude/skills/impossible-guitar-parts/impossible_gate.py \
  --source songsterr.gp --checkpoint songsterr.gp --promote CANDIDATE.gp --examples \
  --stem-source c-tied.gp \
  --audio "03 - The Mutiny-RhythmGtr [R].wav" \
  --beat-map beats_to_seconds.json \
  --transform tie-chain-repair --edit-scope "Rhythm bars 3-8" \
  --changed-notes changed.json

Save the validated map to beats_to_seconds.json first. The [R] channel is the one that passed at 73.6% alignment with 2.22% bar CV, and the stereo sum was rejected at 7.20% with ten bars off, so the flag has to point at the channel rather than the folder.

Expected outcome: the gate returns best_validated_so_far with verdict FAIL, which per the condition means the job is still INCOMPLETE. That is the correct and useful result. It gives every later song a baseline to be measured against.

The two blocked songs have one unblocking step

Asleep in the Trunk and Jackie need a Moises six-stem re-separation before the condition's --audio requirement can be met. A demucs 6-stem pass exists today for exactly those two at BandBooks/BELIEVEYOUME/3-guitar-derivation/_demucs_6s/htdemucs_6s/ with a guitar.wav each, so the cheaper first move is testing whether that guitar file passes map_health_gate.py. If it does, both songs unblock with no new separation. If it fails, run the Moises role split, which is what produced the usable stems on the other five.

Per-pass checklist, identical every time

  1. Re-pull the live tab and run empty_staff_gate.py, since a full-size file with a zero-note staff clears every presence check
  2. Build the beat map on the single best isolated guitar channel, and run map_health_gate.py. A map that beats a random control can still be degenerate
  3. Run audio_accuracy_audit.py including the new duration measure, each number beside its own control
  4. Run the five-tier playability grade
  5. Itemise and classify every discrepancy
  6. Run impossible_gate.py with the full flag set so comparison_basis and the ledger entry are written

Nine passes at Phase 1's demonstrated cost. Steps 1 to 2 are the ones that fail loudly and cheaply, so a song that cannot produce a healthy map stops at step 2 rather than consuming a whole pass.

6. Phase 3: repair the conditions, close the canon goal

3.1 Rewrite the community-os condition against real state

Replace the "only the 32 line worked sample is ingested" clause with the measured corpus, and keep the mechanism the clause was protecting: a green gate proves plumbing and never proves corpus content. The new wording should demand a surfaced os.py list and os.py sources per run, which stays correct as the corpus grows rather than pinning a number that goes stale again.

3.2 Run the four canon gates with exit codes off the pipe

for g in validate_citations lint_canon test_source_gate test_canon; do
  python3 "$g.py" > "/tmp/$g.out" 2>&1
  echo "$g exit=$?"     # captured before any pipe touches it
  tail -5 "/tmp/$g.out"
done

The condition calls out the pipe trap explicitly, because a pipe reports the last command's status and not the script's. Surface the counts alongside: citation tokens, record counts by kind, and the check counts from both test files.

3.3 Give the other pipelines a condition, or say plainly that they have none

Two of 73+ skills carry a /goal. The book pipeline, the tarot corpus, the Etsy delivery audit and the stem players all ship artifacts under hard gates with no completion condition above them. Writing conditions for all of them is a larger project than this plan covers. The honest close is a short register of which pipelines have a condition and which do not, so an absent condition is visible rather than assumed.

7. The one decision that is not mine

Phase 1 and Phase 2 do not answer whether the inherited tab is correct.

Nine measures were run across two songs with controls on both sides. Attack recall is the unique survivor at 5.70x. Pitch agreement has no discriminating power on every healthy map (+2.4, +2.6, +3.6). Ownership was refused at -0.0115. Per-bar support came in at +4.7 against a +15.0 requirement. Nothing says the tab is wrong. These tools cannot tell on this material, and each one says so about itself.

So a note-by-note correction cannot be justified today, and three routes are open:

RouteWhat it costsWhat it gets
Accept the inherited tab with its profilePhase 1 plus nine Phase 2 passesTen songs each carrying a measured accuracy and playability profile, a ledger entry, and a lineage block. The condition returns complete on the requirements it can test, with the untestable ones stated
Fund the missing-signal workOpen-ended researchThe search space is mapped: continuous spectral features are ruled out, and what is untried is a learned or template matcher on discrete events
Correct by earYour listening time, one song at a timeCorrections the tools record as evidence rather than license. Your ear outranks the scorecard, and each correction becomes an executable regression case

My recommendation is the first route, with the third running alongside on any song where you hear something wrong. It is the only route that reaches a defensible complete on both conditions using evidence in hand, and it leaves the research route open rather than foreclosing it. The measured profile is worth having on all ten songs whichever route follows.
