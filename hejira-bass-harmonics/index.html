The harmonics Jaco played, and the four transcriptions that miss them

Brandon named three natural harmonics by ear: G string 5th fret, D string 7th fret, D string 9th fret. Not one published source has all three. The isolated bass stem has all three. This is the record of settling that from the audio, and of the corrected tab that came out of it.

1. The three nodes

All others get that wrong, though the live one gets close.

The passage is played fretless, on natural harmonics. Stated as touched frets, which is how a bass player thinks about it, the three nodes and their sounding pitches are fixed by the string tuning alone.

Touched nodePartialSoundsMIDIHz
G string, 5th fret4th, +24G467392.0
D string, 7th fret3rd, +19A357220.0
D string, 9th fret5th, +28F#466370.0

Why the coordinate system matters

A natural harmonic decouples the fret from the pitch. The finger touches fret 5 and the string sounds two octaves up. Every format that matters stores the touched fret, so a spec given as "G string 5th fret" maps one to one into both Songsterr's harmonicFret and Guitar Pro's HarmonicFret, with no inference.

2. What four sources say

Two engraved charts from jonimitchell.com and two Songsterr tabs were checked against the three nodes. The Sardi chart was decoded from its TAB staves, the Blackburn chart from its noteheads, the Songsterr tabs from their note JSON.

Blackburn's ten harmonic circles engrave F#4, G#4 and B4. Only F#4 is one of the three. G#4 and B4 do not fall out of standard tuning as clean natural harmonics at all. Sardi's 28 pages carry the D string 7th and 9th fret positions in quantity and carry the G string 5th fret position zero times across the whole song.

"The live one gets close" is measurably true

Coyote live 4448708 is the only human-edited tab of the three, and it writes A3, the D string 7th fret pitch, 29 times against the Hejira AI tab's zero. It writes them as ordinary fretted notes with no harmonic marking, and its C4 ceiling puts G4 and F#4 out of reach. Close, by the exact margin Brandon described.

3. The recording settles it

The question of whether the G string node belongs to Hejira or to Coyote was answerable from the audio, so it was answered there rather than asked. The isolated bass stem was separated with htdemucs_6s from the 401.23 s album track. An STFT at n_fft 8192, 2.69 Hz bins, looks for each node's sounding pitch as a near pure tone, requiring the band to sit in the top 1 percent of prominence and to beat the open string's own fundamental by 2.5 times. That ratio is what separates a natural harmonic from a fretted note, which arrives with a strong fundamental and a full overtone stack.

NodeSoundsSustained eventsLongestAt
G string 5th fretG48 2.60 s359.26 s
D string 7th fretA32 1.72 s34.13 s
D string 9th fretF#412 1.07 s42.72 s

The G string 5th fret harmonic is in the recording eight times, including one that rings for 2.6 seconds, and Sardi's 28 page chart writes it zero times. At that longest event the Songsterr AI tab prints a whole bar rest. Bar 128 is 2.824 s at 85 bpm, so a 2.60 s harmonic was transcribed as silence.

Stated honestly

This is spectral detection with a threshold heuristic, so it is strong evidence rather than proof. The event count and the 2.6 second duration are hard to explain as an artefact, and the onsets give concrete places to listen.

4. How 17 harmonics became 383

An earlier build wrote the harmonics into the Songsterr export by modifying notes in place, on the stated rule that this is structurally neutral, cannot misfill a bar, and leaves the note count unchanged. All of that is true. The file was still wrong, in a way no structural check could see.

A <Note> in a .gp file is not a note

GPIF deduplicates. <Note> and <Beat> elements are shared definitions referenced by id from many places. In this file 181 of 295 Note elements and 293 of 1299 Beat elements are referenced more than once. Note 147 alone is referenced from 32 positions. The 16 notes edited in place are referenced 177 times between them.

Run through Songsterr's own /data/convert endpoint, which is the converter the site itself uses on import, the damage is exact and measurable.

Harmonics0 383 112 measures 18 17 measures

Bars and voices are not shared in this file, 705 of each with a reference count of one, so the repair is copy-on-write down two levels of the ownership chain.

bar   -> voice     unshared, edit its <Beats> list directly
voice -> beat      clone if refcount > 1, then it is private
beat  -> note      always clone, then it is private

The gate that was missing

Every earlier check asked whether the file was structurally sound, and every one of them passed, because bar durations genuinely never changed. Reference count is the only thing that separates a surgical edit from a broadcast edit. The new gate asserts that each edited note is reachable from exactly one position, and that the total position count moved by exactly the intended amount.

Two traps that follow from the same fact

A dedup key on a note id is wrong. Skipping an event because that note is already used rejects genuinely distinct positions that happen to share a definition. Keying on bar plus ordinal recovered two dropped placements. An export shows fewer note elements than positions. Songsterr's own export of 18 harmonic positions carries 3 harmonic Note elements, one per distinct shape, so counting elements there shows a loss that did not happen.

5. The import that was never blocked

Getting a corrected file back into Songsterr had been recorded as closed after five methods failed with no upload request and no success message. All five were run through a browser bridge whose JavaScript executes in an isolated world. It shares the DOM and nothing else.

pointer sequence opens a controlnoyes

The handler had been attached the whole time. The verdict "the click never reached the app, onchange is still null" was measuring the world boundary rather than the click. Injecting a script element reaches the main world, where the app's own import handler is an ordinary function that can be called directly, so no trusted event is needed at any point.

var r = await fetch('http://127.0.0.1:8791/hejira_bass_HARMONICS_v4.gp');
var f = new File([await r.blob()], 'hejira_bass_HARMONICS_v4.gp');
await importRevisionInput.onchange({target: {files: [f]}});
// -> Successfully uploaded hejira_bass_HARMONICS_v4.gp   51,201 bytes   1.03 s

The handler posts the file to /data/convert as form field source and dispatches the returned parts into the editor. That endpoint is a pure function reachable with a plain credentialed fetch, which is how the 383 harmonic corruption was caught before anything was imported, by converting each candidate build and comparing per part note counts against the untouched export.

Three bass bars changed note count, and all three are accounted for. Bar 128 goes from 0 to 1, the whole bar rest replaced by the 2.60 s G4 harmonic the stem carries. Bars 109 and 116 each gain one note, because the note replaced there was a tie origin and the harmonic drops that tie. A natural harmonic is its own attack, so the following note is no longer absorbed into it. Bar sums stay exact at 4.0 throughout.

The harmonics sit at bars 12, 13, 16, 23, 46, 53, 63, 67, 80, 82, 87, 90, 108, 109, 116, 128, 135, counting from 1 as the tab does. Placement is reliable early and drifts late: the tab runs 141 bars at a flat 85 bpm for 398.12 s against 401.23 s of audio, a 0.78 percent gap that accumulates to 1.10 bars by the end of the song.

7. The one open decision

Publishing has not happened and will not happen unasked

Tab 6072564 was authored by 076runner. Import changes editor state only. Verified after the import: revisionId 7930670, revision count 1, 5 tracks, createdVia AI, the published tab untouched.

Submitting a revision is outward facing and overwrites a public tab, so it stays Brandon's act. The Submit control was enabled the entire time and was deliberately not pressed.
